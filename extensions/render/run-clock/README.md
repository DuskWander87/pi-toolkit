# run-clock

把「这次请求已经跑了多久、生成了多少 token、这一轮思考了多久」显示在输入框上方一行：`✳ Perusing… (5s · ↓ 564 tokens · thinking for 2s)`。一条计时器贯穿整段请求，思考、流式输出与工具执行都不停表。请求期间 Pi 的 working 行整行关闭，不留 spinner 与默认文案，位置由一个 `aboveEditor` widget 提供；请求结束后计时行消失，working 行的可见性交还 Pi 的默认设置。动词每次请求抽一个、请求期间不变，配合跑马灯与来回跳的字形一起动。工具调用条数交给 `tool-run-groups` 的摘要行，这一行不重复统计。

## 预览

```text
✳ Perusing… (5s · ↓ 564 tokens · thinking for 2s)
┌──────────────────────────────────────────┐
│ ❯ 跑一遍测试并修掉失败的用例             │
└──────────────────────────────────────────┘
```

文案随请求推进：

| 时机 | 文案 |
|---|---|
| 请求进行中，还没收到用量 | `✳ Pollinating… (3s)` |
| 已有助手消息结束 | `✳ Pollinating… (12s · ↓ 243 tokens)` |
| 模型正在思考 | `✳ Pollinating… (12s · ↓ 243 tokens · thinking for 4s)` |
| 思考结束 | 那一格撤掉，回到 `✳ Pollinating… (12s · ↓ 243 tokens)` |
| 生成量上千 | `✳ Pollinating… (4m 48s · ↓ 23k tokens)` |
| 超过一小时 | `✳ Pollinating… (1h 5m · ↓ 120k tokens)` |
| 请求结束 | 计时行消失；working 行的可见性交还 Pi 的默认设置（下一次请求仍被本扩展关闭） |

耗时从 `agent_start` 起表，换算与 Pi 自己的工具耗时同一口径：不足一分钟按秒（`42s`），到分钟换成 `5m 18s`，到小时换成 `1h 5m`；秒以下的小数去掉了，否则这一行每秒都在闪。省略号表示请求还在进行。token 数取累计的生成量（`usage.output`，含推理 token），工具结果消息不计入；显示时按 Pi footer 的同一口径缩写：千以下原样，万以下一位小数（`2.5k`），百万以下四舍五入到千（`23k`），千万以下一位小数（`2.5M`），再往上取整（`13M`）。思考耗时用同一套耗时换算，统计的是当前这一块思考，多轮之间不累加。只在 TUI 模式动作；print / RPC 模式不动输入框上方与 working 行。

## 特性

### 动画

- **字形**：行首 `✳` 位置上是一个来回跳的单字符，帧序列 `· ✢ ✱ ✶ ✻ ✽ ✽ ✻ ✶ ✱ ✢ ·`，120ms 一跳，走完一圈 1.44 秒。字符组与节拍取自 Claude Code 的 spinner。用 `✱`（U+2731）而不是 `✳`（U+2733）：后者会被 emoji 规则判成双宽，逐帧切换时整行横向抖动
- **跑马灯**：动词与省略号共用一条色带，亮带（色标终点色）在词内来回扫过，1.4 秒扫一趟；相位按连续时间取，所以滚动是平滑的，只有重绘按 120ms 一节
- 动词在这条线上是唯一会变的部分：字形与亮带都在动，耗时、用量、思考三格只有数字变

### 颜色

色标按主题明暗分两套：暗色主题 `#d77757` → `#e3997a`，浅色主题压深到 `#a8492f` → `#b85c3a`，浅底上也能看清。字形取色标起点色，与动词连成一体；耗时、用量、思考三格用主题的 `muted`，与动词拉开层次。颜色按主题的终端色彩模式生成，256 色终端自动降级。

## 安装

```bash
git clone https://github.com/DuskWander87/pi-toolkit
pi install ./pi-toolkit/extensions/render/run-clock   # 安装
pi -e ./pi-toolkit/extensions/render/run-clock        # 只试用一次，不写入配置
pi remove ./pi-toolkit/extensions/render/run-clock    # 卸载
```

在 clone 的上级目录执行，已经有仓库时跳过 `git clone`。更新时在 clone 目录执行 `git pull`，然后在 Pi 中 `/reload`。装齐全部扩展见[根 README](../../../README.md#快速开始)。

## 用法

- 没有配置项，装好即生效
- 计时覆盖整段请求；模型思考、流式输出与工具执行都算在内
- 用量只算生成：输入与缓存读写不进这一行，那部分看 Pi 的 footer
- 思考那一格只在思考进行中出现：思考一结束就撤掉，所以它不会留在请求后面，也不会跨轮累加
- 行首不再有 Pi 的 spinner，请求期间 Pi 的 working 行整行关闭；这一行取代它
- 动词从固定词表（`Pollinating`、`Pondering`、`Tinkering` 等 30 个）里随机抽，每次请求换一个；同一请求内保持不变，抽到上一次用过的词时重抽一次

## 与其他扩展

- 单独安装即可工作
- 与 `minimal-tools` 一起装时，工具行只留调用行；单条命令的耗时不再逐条显示，整段请求的耗时在这一行
- 与 `tool-run-groups` 一起装时，摘要行给思考耗时与工具条数，计时行给整段请求耗时、生成量与当前这一块思考的用时
- 与其它改写 working 行文案的扩展一起装时，本扩展在请求期间关掉 working 行，那些文案不显示

## 限制

### 依赖

- `ui.setWidget`、`ui.setWorkingVisible`，以及 `agent_start` / `agent_end` / `message_end` / `message_update` 四个事件
- 思考耗时读 `message_update` 里的 `thinking_start` / `thinking_end`：供应商不把思考作为独立块流式下发的，这一格不出现
- widget 的位置、宽度与背景由 Pi 提供，不在本扩展控制范围内；Pi 改版后文案可能不再显示在预期位置
- `agent_end` 时用 `setWidget(key, undefined)` 清掉计时行，并 `setWorkingVisible(true)` 把可见性交还 Pi 的默认设置，避免 `false` 残留到本扩展没接住的请求

### 已知问题

- 请求结束后计时行消失，历史回放里没有这段耗时、用量与思考
- token 数在每条助手消息结束时才更新：流式正文期间数字不动，一轮回复结束或转入下一次工具调用时跳一次；Pi 的流式事件不带可靠的实时用量
- 动画按 120ms 一节重绘，一个请求期间约每秒 8 次 `setWidget`；同一节内文案与字形都没变时跳过重绘
- 思考耗时与整段耗时用同一套换算，不足一秒记作一秒；思考块之间的间隙不计入任何一格
- Pi 默认 working 行里的中断提示（`esc to interrupt`）请求期间不再显示；中断键仍可用
- 与其它占用输入框上方 widget 或改写 working 行的扩展在同一位置重合时，最后写入的那个生效

### 非目标

- 不写会话数据
- 不统计整段会话的历史用量：累计范围只有当前这次请求
- 不追踪多块思考的合计：只显示正在进行的这一块

## 实现原理

- `agent_start`：抽一个与上一次不同的动词、记下起点、清掉上一轮的思考状态，关掉 working 行，立刻写一次计时行，之后每 120ms 重绘
- `message_end`：助手消息带用量时把 `usage.output` 累加进本次请求并立即重绘
- `message_update`：`thinking_start` 记下起点、`thinking_end` 清掉它，两次都立即重绘；其它流式事件直接返回
- `agent_end`：清掉 `setInterval`，移除计时行，并把 working 行的可见性交还 Pi 的默认设置
- 文案格式固定为 `<字形> <动词>… (<耗时> · ↓ <tokens> tokens · thinking for <耗时>)`，缺哪格就整段省掉；耗时按秒 → `5m 18s` → `1h 5m` 换算，tokens 按 footer 口径缩写，位数固定，逐拍重绘不抖动
- 字形与跑马灯都只依赖「距起表多少毫秒」：字形按 `floor(ms / 120) % 12` 取帧，跑马灯把 `ms` 归一成 0~1 的相位后逐字符取色，因此掉帧只是跳过一拍，不会累积偏移
- 动词与省略号用 `foregroundAnsi` 逐字符设前景色，色标按 `theme.appearance` 在两套之间选，末尾以 `\x1b[39m` 复位，再接 `theme.fg("muted", …)` 的后缀
